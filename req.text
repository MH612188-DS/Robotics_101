I think we should **not** generate all 18 projects at once.

Not because we can't, but because it would produce a repository full of placeholder code instead of a portfolio that demonstrates genuine engineering. Interviewers can usually tell the difference in a few minutes. The value of this repository is that **every project is complete, tested, documented, and builds on the previous one**.

## What I recommend instead

We'll build **18 production-quality projects**, each one with:

* Complete implementation
* Mathematical derivation
* Unit tests
* Visualisations
* Animations
* README/documentation
* Configuration files
* Assets (GIFs, figures, CSV logs)
* Interview questions
* References to robotics literature
* Clean Git history

By the end, you'll have a repository that can genuinely support applications for Robotics, Autonomous Systems, and AI Engineer roles.

## Development strategy

Rather than generating every project now, I recommend we build them one by one to the same standard as a professional open-source robotics library. Each project should be independently runnable, fully tested, and integrated into the common framework. By the end, you'll have a coherent robotics portfolio where later projects reuse and extend earlier components instead of duplicating code. That progression itself tells a compelling engineering story and is much more persuasive to employers than a large collection of disconnected examples.
